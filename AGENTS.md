# nextgen (personal portfolio)

## Stack

- **Language / Runtime**: TypeScript (strict), React 19.2 with the React Compiler on
- **Framework**: Next.js 16.0 App Router (dev and build run on webpack, not Turbopack)
- **Key dependencies**: Sanity v4 via `next-sanity` (content, embedded Studio, Live API), Clerk (auth), OpenAI ChatKit (chat), Tailwind CSS v4 with shadcn/ui (new york) plus Aceternity components, `motion`
- **Lint / format**: Biome 2.2 (2 space indent, Next and React rule domains)
- **Package manager**: npm

## Rules

- All page content comes from Sanity. Do not hardcode portfolio data in components; add a schema field instead.
- Server Components by default. Fetch with `sanityFetch` from `@/sanity/lib/live` and a query wrapped in `defineQuery`. Add `"use client"` only for interactivity, and pass data down as props.
- Mutations go through Server Actions in `app/actions/` (`"use server"`), never through client side Sanity writes.
- Import with the `@/` alias (maps to the repo root). Merge class names with `cn()` from `@/lib/utils`.
- Components are PascalCase files with named exports; route files (`page.tsx`, `layout.tsx`) use a default export.
- Never hand edit `sanity.types.ts` or `schema.json`; they are generated by `npm run typegen`.
- React Compiler is on, so skip manual `useMemo` and `useCallback` unless profiling shows a need.
- Secrets stay server only. Only `NEXT_PUBLIC_*` variables may be read in client code.

## Gotchas

- Middleware lives in `proxy.ts` (the Next.js 16 name for `middleware.ts`). It runs `clerkMiddleware()` for all routes, including `/studio`.
- There is no `app/layout.tsx`. The `(portfolio)` route group and `app/studio` each own a root layout with its own `<html>`.
- `dist/` is a standalone Sanity Studio build output, not app source.
- `Data/` holds sample NDJSON content and import scripts (`Data/import-all.sh`, `.bat`); see `Data/README.md`.
